## 0. 이 문서가 서 있는 자리

### 0-1. 입력을 세 등급으로 나눈다

초안 기획서는 입력을 "실사용자 페르소나 5인의 2주 사용 리뷰"라고 적었다. **그건 사실이 아니다.** git 이력이 반증한다.

```
caafc51  2026-09-17 07:52  feat(ui): 6단계 UI — 오늘·일지·설정 화면, 빠른 메모 창
f0dcc7d  2026-09-17 10:11  feat(ui): 설정 › 모양 — 테마·글꼴·글자 크기
74e729e  2026-09-17 11:55  feat(history): 지난 날짜 타임라인
580306e  2026-09-17 13:48  feat(journal): 일지 템플릿 3종
f245ac5  2026-09-17 13:48  chore(release): v0.2.1
```

리뷰 다섯 건이 상세히 평가한 '모양' 탭, 템플릿 3종, 지난 날짜 이동, `Worklog_0.2.1_x64-setup.exe` 는 전부 **오늘 커밋**이다. 누구도 이것을 2주 쓸 수 없었다. 리뷰 5건이 전원 "2주"로 일치하고 전원이 같은 샘플의 같은 문자열(`23h 32m`, `<recommended_plugins>`)을 인용하는 것도 단일 생성기의 서명이다.

그래서 이 문서는 입력을 세 등급으로 나누고 **등급 A 만 판단의 근거로 쓴다.**

| 등급 | 내용 | 이 문서에서의 용도 |
|---|---|---|
| **A · 검증된 사실** | 저장소 코드(`analyze.rs` · `render.rs` · `store.rs` · `template.rs` · `config.rs` · `output/*`), 실데이터 샘플 일지(2026-09-16, 표준 템플릿, 실제 dry-run 산출물), `docs/v2-plan.md` 의 결정·관찰 기록, **Python v1(0.1.19, 2026-07-10 릴리스 → 2026-09-17 컷오버)의 약 2개월 저자 도그푸딩** | 결함 판정 · 우선순위 · 성공 기준 |
| **B · 설계 의도** | 와이어프레임 annotations, README, `v2-plan` §0·§9 | "원래 무엇을 만들려 했는가" 대조 |
| **C · 합성 가설** | 페르소나 5인 리뷰(생성물, `docs/persona-reviews.md`) | **가설 목록으로만.** 점수·세그먼트 크기·지불 의사는 폐기 |

**중요한 단서 하나.** 합성 페르소나가 제기한 항목 중 셋 — 집중시간 과다 합산, 타임라인 오염, 주간 부재 — 은 **페르소나 없이도 성립한다.** 샘플 일지와 코드에서 직접 확인되고, 앞의 둘은 `v2-plan §9` 에 이미 "다음 과제"로 저자 본인이 적어 두었다. 이 세 개는 등급 A 로 승격해 그대로 쓴다. 나머지는 §부록 B 의 가설 목록으로 내린다.

### 0-2. 제품 형태를 한 줄로 확정한다

초안은 포지셔닝 맵·세그먼트 우선순위·D7/D14 잔존율·"유료화 후보 1순위"를 썼다. 전부 다수 사용자를 전제한 언어인데, 실제로는 배포 채널이 서명 없는 GitHub Releases 하나, 획득 경로 0개, 가격 0줄, 사용자 1명이다.

> **확정: ① 저자 개인 도구. 조건을 충족하면 ② Hecto 사내 도구로 승급한다.**
>
> **승급 조건(셋 다 충족해야 함)**
> 1. 사내 저장소 세션 질답의 외부 LLM 전송이 회사 정책상 허용됨을 문서로 확인 — 또는 제외 목록으로 그 경로를 원천 차단.
> 2. 나가는 내용을 한 화면으로 설명할 수 있음(미리보기 + 전송 이력).
> 3. Windows 코드 서명 착수.
>
> ③ 외부 배포 제품은 **현재 고려 대상이 아니다.**

이 확정의 귀결:

- 포지셔닝 맵 · 세그먼트 우선순위(Primary/Secondary/Deferred) 표 **삭제**. 1명짜리 시장에 세그먼트는 없다.
- 잔존율 · 온보딩 완주율 · TTFV · 유료화 판단 **삭제**(§7 에서 "측정 경로 미확보"로 명시).
- 코드 서명은 "조건부 Later" 가 아니라 **승급 조건**이다(§5-3 L3).
- 프리랜서 시간 집계(초안 X5, L 난이도)는 **사용자 0명짜리 세그먼트를 위한 대형 작업**이므로 Later 로 내린다.

### 0-3. 그래서 이 문서가 내리는 판단

샘플 일지 한 장이 제품의 현재를 요약한다.

- **위쪽 절반**(`> 한 줄 요약` · `## 오늘의 성과` · `## 결정 · 요청 · 할 일` · `## 프로젝트별 진행`) = LLM 출력. 문장 품질은 좋다. **그러나 사실성이 한 번도 검증된 적 없다** — 커밋 0 인 날에 성과 5줄이 나왔고, 그 줄들이 참인지 확인한 사람이 없다.
- **아래쪽 절반**(`## 지표` · 프로젝트별 집중 표 · `<details>` 타임라인) = 규칙 기반. **틀린 게 확실하다** — 하루짜리 문서에 23h 32m, 표 합계 26시간+, 시스템 주입 문구와 반말 프롬프트가 제목 자리에 앉아 있다.

초안은 "가장 어려운 부분(AI 요약 품질)은 이미 통과했다"고 단정했다. **그 단정을 철회한다.** 근거가 합성 진술뿐이었고, 같은 문서 안에 반증이 있다. 틀린 23h 32m 은 사람이 보면 틀린 줄 안다. "MCP 인증 방향 확정"이 실제로는 확정되지 않았다면 **아무도 모른 채 보고된다.** 이게 더 비싼 실패다.

> **다음 2주의 전부는 세 가지다 — ① 나가면 안 되는 것을 막고, ② 숫자를 맞추고, ③ 문장에 근거를 붙인다.** 그리고 금요일 문제는 새 화면이 아니라 **CLI 한 줄**로 먼저 끝낸다.

## 1. 한 줄 정의 · 제약 · 시간 가설

### 1-1. 한 줄 정의

> **업무일지는, 이미 내 컴퓨터 안에 흩어져 있는 하루의 흔적(커밋 · AI 세션 · 회의 · 내가 남긴 메모)을 자동으로 모아 두었다가, 버튼 한 번에 "남에게 보낼 수 있는 문서"로 바꿔 주는 Windows 로컬 앱이다.**

수집은 **묻지 않고 자동**(파일 감시), 문서화는 **누를 때만**(수동), 결과물은 **주간보고에 그대로 붙는 문장**으로. 데이터는 `~/.worklog` 밖으로 나가지 않고, 요약할 때만 Claude 로 나간다(`v2-plan §0`).

### 1-2. 하지 않는 것 (제약을 앞면에 박아 둔다)

| 하지 않는 것 | 이유 |
|---|---|
| 시간 추적기(스톱워치) · 티켓 관리 · 팀 협업 도구 | 제품 범위 밖 |
| 호스팅형 웹 · 팀 서버 | `v2-plan §0` 의 로컬 전용 원칙. 이걸 깨면 유일한 방어선이 사라진다 |
| **claude CLI 또는 `ANTHROPIC_API_KEY` 가 없는 사용자** | `summarize.rs claude_exe()` 가 PATH 에서 `claude.cmd/exe/bat` 를 찾고, 없으면 `ANTHROPIC_API_KEY`, 그것도 없으면 요약 없음. **이 앱의 핵심 가치는 Claude 구독자 또는 API 과금자에게만 존재한다.** 온보딩으로 풀리는 문제가 아니라 구조 제약이다 |
| 사용자 정의 템플릿 파일 | `v2-plan §9` 결정 유지(프롬프트 편집 노출 위험) |

이 셋째 줄이 중요하다. 초안은 비개발 직군이 막히는 이유를 "온보딩 결함이므로 비용이 낮다"고 분류했는데, 틀렸다. 마법사를 아무리 잘 만들어도 claude CLI 가 없는 사람에게는 "당신은 이 앱을 쓸 수 없습니다"를 더 빨리 알려 줄 뿐이다. 비개발 직군을 진짜로 들이려면 **앱 안 로그인형 과금 경로 또는 로컬 모델**이 필요하고, 그건 M 이 아니라 L 이다(§5-3 L2 · L6).

### 1-3. 왜 지금인가 — 이 제품의 유일한 시계

경쟁 압력도 시장 창도 조직 데드라인도 없다. 그런데 시계가 하나 돌고 있다.

> **Claude Code · Codex 세션 로그는 기본 30일 뒤 사라진다. 지금 수집하지 않은 하루는 영원히 복원되지 않는다.**

이건 이미 인지된 사실이다 — 지난 날짜 스냅샷(`day_feeds`)을 만든 이유가 정확히 이것이다(`v2-plan §9`). 이 가설을 받아들이면 두 가지가 따라온다.

1. **수집이 요약보다 먼저다.** 수집이 끊기는 일(앱을 끄는 회피 행동)은 어떤 UX 불편보다 비싸다 → §5-1 **N0** 를 Now 1순위로 올리는 근거.
2. **git 과거 커밋 백필은 Later 가 아니다.** git 은 과거를 전부 읽을 수 있으므로 난이도가 낮고, 미루면 이득이 줄기만 한다 → §5-2 **X9**.

## 2. 사용자

### 2-1. 지금

**사용자 1명 — 저자 본인.** 하루 20~30 AI 세션, worktree 로 저장소 6~8개, 커밋이 0인 날이 흔하고(샘플 2026-09-16 이 그런 날이다), Hecto 사내 저장소와 개인 저장소가 같은 PC 에 섞여 있으며, 금요일마다 주간보고를 쓴다.

초안은 이걸 "김지훈형 — AI 코딩을 일상으로 쓰는 시니어 개발자"라는 세그먼트로 불렀다. 그건 세그먼트가 아니라 **자화상**이다. 그 집단이 세상에 몇 명인지, 그중 몇 명이 Windows 데스크톱 앱을 설치하는지 숫자가 0개다. 자화상인 걸 인정하는 편이 판단에 유리하다 — 요구사항을 직접 물어볼 수 있고, 검증이 즉시 되고, 틀린 방향이면 하루 만에 안다.

### 2-2. 승급 시(사내 도구)

**Hecto 개발 파트 + 인접 직군.** 이때 필요한 것은 기능이 아니라 §0-2 의 승급 조건 세 개다. 그 전까지 팀 기능(취합·공유·서버)은 만들지 않는다.

### 2-3. 이 제품이 실패하는 단 하나의 시그널

> **저자가 이 앱을 안 쓰게 되는 날.**

1인 도구에서 도그푸딩이 멈추면 개발도 멈춘다. 초안의 리스크 표에 이게 없었다. §8 **R7** 로 넣는다.

### 3-2. D1 이 D2 보다 먼저인 이유

초안은 D2(집중시간)만 고치기로 하고 명시적으로 이렇게 썼다: *"세션 수·파일 수는 그대로 카운트(정보 손실 없음)"*. **이건 원칙 3 을 스스로 위반한다.** 구간 병합(union)은 `minutes` 만 고친다. 수정 후 문서는 이렇게 나온다.

```
| agent-platform-backend | 6h 12m | 20 | 83 |   ← 시간만 맞고, 세션 20·파일 83 은 여전히 3배
- AI **30세션** · 출력 1.3M토큰                  ← 지표 줄도 그대로 부풀려져 있음
```

**틀린 숫자를 하나 지우고 두 개를 남기는 것이다.** 게다가 "합계 > 24h 이면 표 차단" 가드는 검증이 아니라 증상 차단이다. 중복이 2배면 23h 가 12h 가 되고, 가드를 통과하며, 여전히 틀린 값이 나간다 — **가드 통과가 정확성의 증표가 되어 버리는 것이 더 위험하다.**

→ 그래서 §6 상세 A 는 **session_id 정규화를 1순위**로, 구간 union 은 그 다음(창 열어 둔 idle 처리용)으로 재정의한다.

## 4. AX 원칙 5개

> 기능 제안이 들어오면 이 다섯으로 채점한다. 초안의 다섯 개 중 **원칙 3·5 는 그대로**(제품 판단 기준으로 실제 작동한다), **원칙 1·2 는 1인 도구 기준으로 축소**, **원칙 4 는 "보이게"에서 "막을 수 있게"로 강화**했다.

### 원칙 1 — 설정 없이도 첫날부터 돌아간다

사용자가 설정을 열기 **전에** 결과를 한 번 보여준다. 설정은 "고치러" 가는 곳이지 "켜러" 가는 곳이 아니다.

지금 위반하는 곳: 개발자 노브가 1급 화면에 있다(`질답 상한 120턴/180자`, `파일 행 상한 200000행`, `긴 날 처리 20000자·4 병렬`). 이것들을 '고급'으로 접는다. 기본 모델 값이 채워져 있는 것도 같은 위반이다(D9).

**1인 도구 기준의 조정**: 온보딩 마법사(초안 X1)는 Next 로 내린다. 사용자가 1명이고 그 1명은 이미 온보딩을 마쳤다. 첫 5분 설계는 **승급을 결정한 뒤**에 만들어야 낭비가 없다.

### 원칙 2 — AI 가 먼저 제안하고, 사람은 승인만 한다

빈칸을 주지 않는다. 항상 채워진 초안을 주고 고치게 한다.

| 적용 지점 | 형태 |
|---|---|
| 세션 제목 | 첫 발화 원문 대신 "그 세션이 뭘 한 세션인지 한 줄"을 붙인다(N2) |
| 주간 보고 | 금요일에 `worklog weekly` 가 초안을 뱉는다. 사람은 읽고 고치기만(N8) |
| 할 일 | 어제 `- [ ]` 를 오늘 문서 상단에 이월 제안(X4) |

### 원칙 3 — 틀린 숫자보다 없는 숫자가 낫다

**이 제품에서 가장 비싼 실패는 "안 보여준 것"이 아니라 "틀리게 보여준 것"이다.**

| 규칙 | 화면·문서에서의 모습 |
|---|---|
| 계산을 신뢰할 수 없으면 표를 빼거나 '추정'을 붙인다 | 집중시간 열 제목 옆 `추정 ⓘ` + "겹치는 세션을 합쳐 벽시계 기준으로 계산" |
| 물리적으로 불가능한 값은 **출력 자체를 막고, 그 사실을 릴리스 차단 신호로 쓴다** | 하루 합계 > 24h 이면 렌더 차단 + 로그. **가드가 한 번이라도 발동하면 릴리스를 막는다** |
| 0 은 0인 이유와 함께만 | `커밋 0 — 훑은 저장소 41개에서 내 작성자(2개)와 일치하는 커밋 없음` / 근거가 없으면 그 줄을 아예 뺀다 |
| **문장에도 같은 규칙을 적용한다** | 근거(커밋 해시 · 편집 파일명 · 회의 제목 · 메모)를 붙일 수 없는 성과 줄은 **쓰지 않는다**. 커밋 0 인 날은 '완료'가 아니라 '진행 · 논의 · 검토'로 서술한다 |

마지막 줄이 이번 개정에서 새로 들어온 것이다. 초안은 이 원칙을 숫자에만 적용했다. **"결정론적 섹션은 LLM 을 안 거치므로 여기서 틀리면 100% 우리 책임"** 이라고 썼는데, 뒤집으면 LLM 섹션이 틀리면 책임이 없다는 뜻이 되어 버린다. 사용자는 그 구분을 하지 않는다.

### 원칙 4 — 나가는 것은 보이고, 고를 수 있고, **막을 수 있다**

로컬 전용은 **아키텍처로 이미 지켰다**(`v2-plan §0`). 남은 건 두 가지다.

| 지금 (위반) | 바뀐 뒤 (준수) |
|---|---|
| 보호 수단이 '전역 끄기' 하나 — 켜거나 안 쓰거나 | **저장소·폴더 단위 제외 목록(글롭).** 제외된 항목은 수집은 되되 요약 프롬프트에서 빠지고, 문서에는 집계만 남는다 |
| 설정 › AI 요약에 "무엇이 나간다"는 문장이 0줄 | 고정 문구 한 줄 + 생성 직전 "세션 30건 · 약 18만 자 [내용 보기]" |
| 비밀값이 `settings.json` 평문 | DPAPI/Windows 자격 증명 관리자 + 보관 정책 |

**"막을 수 있다"가 "보인다"보다 먼저다.** 회피 행동(규정 있는 날 앱을 끄는 것)은 그날 하루를 통째로 날리고, 세션 로그는 30일 뒤 사라진다(§1-3). 미리보기는 안심을 주지만 제외 목록은 데이터를 지킨다.

### 원칙 5 — 실패는 조용히 복구하되, 조용히 넘어가지는 않는다

**이미 잘 지킨 곳**: 설정 › 정보의 '최근 생성' 표(실패 원인 + '다시 시도'), 생성 취소, 편집된 일지 보호, 놓친 시각 동작 복구(`kv.app.last_alive`).

**어긴 곳**: claude CLI 가 없을 때. 요약을 건너뛰고 **"저장했습니다(AI 요약 없음)"** 로 성공 처리한다. 사실을 알려면 설정 › AI 요약 탭까지 들어가야 한다.

| 규칙 | 적용 |
|---|---|
| 핵심 가치가 빠진 결과는 성공이 아니다 | 요약 없이 만든 문서는 '부분 성공' 표시 |
| 실패 안내는 그 일을 하려는 화면에서 | '지금 일지 만들기' **버튼 옆**에 "AI 요약 준비 안 됨" 배지 |
| 복구는 한 번의 클릭 | 배지 클릭 → "claude CLI 설치 안내 복사" / "API 키로 대신하기" / "요약 없이 만들기" |

### 상세 A — 신뢰 가능한 지표와 **검증 가능한 문장** (N1 + N2 + N3 + N4)

#### 문제

샘플 일지 한 장 안에서 네 가지가 동시에 일어난다.

```
- 커밋 **0** (+0/−0) · 저장소 0 · AI **30세션** · 출력 1.3M토큰 · 회의 2건 · 활동 07:32–17:44
                                                              ← 활동 구간 약 10시간
| agent-platform-backend | 23h 32m | 20 | 83 | 0 | – |        ← 한 프로젝트가 23시간 32분
표 전체 합계 ≈ 26시간                                          ← 하루는 24시간

- `08:36–14:27` 🤖 보통 이런식으로 만들기도 하는거야 근데? · agent-platform-backend
- `08:36–14:27` 🤖 보통 이런식으로 만들기도 하는거야 근데? · agent-platform-backend   ← 같은 세션 3번
- `13:06–13:13` 🤖 <recommended_plugins>…                                          ← 시스템 주입 문구

## 오늘의 성과
- [agent-platform-backend] MCP 서버 인증 방향 확정(OAuth+PAT 2갈래, B안) …
                                    ↑ 커밋 0 인 날. 이 "확정"이 참인지 아무도 모른다
```

#### 해결 — 순서가 중요하다

**1단계. 정규화 (원인 제거).**
- `session_id` 기준 dedup 을 **수집/정규화 단계**에 넣는다. 같은 세션은 한 번만 센다.
- 세션 cwd → `repos.common_dir` 로 해석해 worktree 를 한 프로젝트로 묶는다(`store.rs` 가 이미 `common_dir` 를 PK 로 쓴다. `service.rs disambiguate_repo_names()` 근처에 붙인다).
- → **`minutes` · `sessions` · `files` · `tokens` 가 한 번에 맞는다.**

**2단계. 집계 (남은 오차 제거).**
- 프로젝트별로 `[first_ts, last_ts)` 구간을 모아 정렬 → 겹치면 합침 → 합집합 길이를 집중시간으로.
- 구간 안에서 연속 이벤트 간격이 임계(기본 30분, 설정 가능)를 넘으면 뺀다. "창 열어두고 점심"이 빠진다.

**3단계. 안전장치 (버그 탐지기로 쓴다).**
- 프로젝트 합계 또는 총합이 24h 를 넘으면 표를 렌더하지 않고 "집중시간 계산 불가(겹침 과다) — 세션 수 · 파일 수만 표시"로 대체.
- **동시에 로그를 남기고, 가드가 한 번이라도 발동하면 릴리스를 막는다.** 사용자에게 "계산 불가"를 보여주는 건 최후 수단이지 설계 목표가 아니다.
- 표 제목을 `**프로젝트별 집중** (추정 ⓘ)` 로. 툴팁: "겹치는 세션을 합치고 30분 이상 빈 구간을 뺀 벽시계 기준값입니다."

**4단계. 제목 정제**(`render.rs` 신규 `clean_title()` — `session_head` · `emit_session_titles` · `render_session_blocks` · `analyze.rs` 타임라인 title 이 전부 경유).
- 차단 접두: `<recommended_plugins`, `The following is the Codex agent history`, `Traceback (most recent call last)`, `Call the MCP tool`, `Do the following with MCP tools`, `Read <경로>`
- 로컬 절대경로(`D:\…`, `C:/Users/…`)는 파일명만 남기고 축약
- 코드블록·붙여넣은 로그로 보이면(줄 수 > 3 또는 `File "` 포함) 제목 후보에서 제외
- 차단되면 다음 후보로 폴백: 두 번째 사용자 발화 → 편집 파일명 → `[프로젝트] 세션`

**5단계. 0 의 이유.** `render_metrics_line()` 이 0인 항목은 기본 생략. 커밋 0인데 저장소는 발견된 경우 근거 한 줄을 붙인다.

**6단계 — 이번 개정에서 새로 들어온 것. 문장에 근거 앵커.**

`template.rs` 프롬프트에 세 줄을 추가한다(난이도 S, 0.5일).

```

   회의 제목 · 메모 중 하나. 근거를 붙일 수 없는 줄은 쓰지 마라.
```

### 상세 B — 주간 모아보기: **CLI 먼저, 앱은 나중에** (N8 → X1)

#### 문제

설계 문서에 답이 이미 적혀 있다. `v2-plan §9`:

> "'오늘의 성과'와 '결정·요청·할 일'은 모든 템플릿 공통 — **주간 보고가 이 둘만 모으면 되게.**"

**모으는 쪽이 안 만들어졌다.** 자동화의 마지막 한 칸이 비어서 매주 사람이 손으로 채운다.

#### 왜 쪼개는가 — 초안은 이걸 "M · 3일"로 잡았다

초안 계획표는 9/29~10/1 **3일**에 이 전부를 넣었다: 신규 템플릿 + `generate_range()` + 스키마 v4 + Tauri 커맨드 2개 + UI 탭 + CLI 플래그 2개. 마지막 날은 릴리스 준비와 겹친다. 코드를 보면 왜 3일이 아닌지 보인다.

```rust
// store.rs
pub const SCHEMA_VERSION: i32 = 3;
CREATE TABLE IF NOT EXISTS documents ( date TEXT PRIMARY KEY, … );

// output/markdown.rs
let path = out_dir.join(format!("{}.md", worklog.target_date));

// output/notion.rs — 매 생성마다
self.request(POST, "{api}/pages", …)            // 같은 날짜 페이지가 계속 늘어난다

// output/obsidian.rs
pub const MARKER: &str = "tags: [업무일지]";      // 표식만 보고 확인 없이 덮어씀
```

**주간 문서는 단일 날짜가 없다.** `documents` 는 `date` 가 PK 고, 로컬 md 는 `{date}.md` 고정, Obsidian 은 표식으로 덮어쓰기를 판정하고, Notion 은 매번 새 페이지를 만든다. 여기에 `document_get / put / mark_edited / dates / statuses` 전체와 Journal 화면 달력이 date 키 가정 위에 서 있다. **주간 기능을 켜는 순간 Notion 에 주간 문서 중복까지 쌓인다** — D10 을 하나 더 만드는 것이다.

#### 해결

**N8 — 주간 v0 (Now, 1주차, S~M): CLI 전용, 저장 없음**

| 구성 | 내용 |
|---|---|
| 데이터 | `store.document_dates()` / `document_statuses(from,to)` / `day_kpis(from,to)` — **이미 존재** |
| 파싱 | 각 날짜 문서에서 `## 오늘의 성과`, `## 결정 · 요청 · 할 일` 블록만 추출. 제목이 `template.rs` 상수(`T_WINS`/`T_DECISIONS`)로 고정돼 있어 안정적 |
| 합치기 | 성과는 `[프로젝트]` 태그로 그룹핑 후 날짜 역순 → 유사 항목 병합(**LLM 1회**, 입력 수천 자) · 결정은 날짜와 함께 나열 · `- [ ]` 중 **마지막 날까지 체크되지 않은 것만** '남은 할 일'로 |
| 신규 템플릿 | `weekly` — `## 이번 주 성과(프로젝트별)` · `## 결정 · 요청` · `## 남은 할 일` · `## 지표(주간 합계)` |
| 없는 날 | "9/17 (목) — 일지 미생성" 으로 표시. 침묵하지 않는다(원칙 5) |
| 출력 | **stdout 또는 `--out <path>`.** `documents` 에 쓰지 않는다 → 스키마 변경 0 |
| 명령 | `worklog weekly` · `worklog --from 2026-09-14 --to 2026-09-18 --template weekly` |

**파싱 실패 대비(초안이 놓친 것).** 편집된 문서는 섹션 구조가 깨져 있을 수 있다. 섹션을 못 찾으면 **조용히 빠뜨리지 말고** "9/16 — 섹션을 찾지 못해 원문 그대로 포함" 으로 표시하고 그 날 문서 전체를 붙인다. 그리고 **파싱 실패율을 첫 실행에서 측정한다**(§7-1 M7).

**X1 — 주간 앱 화면 (Next, 별도 릴리스)**

카드에 실제 작업을 전부 적는다. 이걸 다 적으면 3일이 아니라는 게 표에서 저절로 보인다.

- `documents` 에 `kind`(`day`|`weekly`) · `period_start` · `period_end` 추가, PK 를 `(kind, period_start)` 로 변경하는 **스키마 v4 마이그레이션**
- `document_get / put / mark_edited / dates / statuses` 시그니처 변경, Journal 달력의 date 가정 수정
- md 파일명 규칙(`2026-W38.md`) · Obsidian 충돌 처리 · **X6(Notion 업서트) 선행 필수**
- 일지 화면 `( 일별 | 주간 )` 탭, 기간 선택, 미생성 날짜 경고
- 편집 충돌 규칙: **편집된 일별 문서로 주간을 다시 만들면 어느 쪽이 정본인가** — 답: 주간은 항상 파생물이고 편집된 일별이 정본이다. 주간 문서에 "9/16 은 편집본 기준" 을 표시한다

| 편집된 일별 문서의 **섹션 파싱 실패율** | **10% 이하** (초과 시 파싱 전략 재설계) |
| 주간 생성 1회 LLM 비용 | 일일 생성 **1회분 이하** |
| X1(앱 화면) 착수 판단 | **N8 을 4주간 실제로 썼는가.** 안 썼으면 X1 을 만들지 않는다 |

마지막 줄이 이번 개정의 핵심이다. 비평은 이렇게 지적했다 — *"사용자가 1명이면 주간 모아보기는 `cat 2026-09-1{4,5,6,7,8}.md | claude "합쳐줘"` 한 줄로 끝난다. N5 에 배정된 3일이 셸 명령 한 줄과 경쟁해서 이긴다는 근거가 없다."* 맞는 말이다. **그래서 N8 은 그 셸 한 줄과 같은 층위(CLI)에서 경쟁하게 만들고, 이기면 그때 앱 화면에 투자한다.**

### 상세 C — 나가는 것 막기: **제외 목록 먼저** (N0 → X3)

#### 문제

로컬 전용은 아키텍처로 지켰는데, **보호 수단이 전부 아니면 전무다.**

`config.rs` 의 `GitConfig` 에는 `repos`(직접 지정) · `scan_roots` 는 있어도 **제외 필드가 없다.** `SummarizerConfig.provider` 를 `"none"` 으로 바꾸는 것이 유일한 차단 수단이고, 그러면 모든 프로젝트의 요약이 함께 사라진다. 설정 › AI 요약 탭에는 `모델` · `최대 토큰` · `긴 날 처리` 만 있고 **"무엇이 밖으로 나가는지"가 한 줄도 없다.**

샘플 일지만 봐도 요약 프롬프트에 무엇이 실렸는지 역산된다: 사내 서비스명(SUDA, KMS), 조직 호칭(의장님, 계열사, HAI본부), 내부 파일 경로(`/app/app/services/KmsUploadService.py`), Traceback 원문, 로컬 경로(`D:\study\ai-web-novel\docs\…`).

**그리고 이건 사용자 리스크이기 전에 저자 본인의 컴플라이언스 리스크다.** Hecto 사내 PC 에서 사내 저장소 세션 질답이 외부 LLM 으로 나가고 있다. 초안은 이 각도를 한 번도 쓰지 않았다.

#### 해결

**N0 (Now, S) — 막는 것부터**

| 구성 | 내용 |
|---|---|
| **제외 글롭 목록** | 설정 › 수집 소스에 `제외할 저장소 · 폴더` 한 칸(글롭 지원: `D:\works\a-corp\**`). `config.rs` 에 `sources.exclude: Vec<String>` 추가 |
| **동작** | 제외된 항목은 **수집은 되되 요약 프롬프트 구성 단계에서 빠진다.** 문서에는 `[비공개 프로젝트]` 로 집계만 남는다 → *"앱을 껐다"가 "하루가 비었다"로 이어지지 않는다* |
| **고지 문구** | 설정 › AI 요약 상단 고정: "요약을 만들 때 **세션 질답 · 커밋 메시지 · 회의 제목 · 메모**가 Claude 로 전송됩니다. 그 외에는 아무것도 나가지 않습니다." (작업 30분) |
| **생성 화면 표시** | '지금 일지 만들기' 아래 한 줄: `제외 2곳(a-corp, payments-core)` |

**X3 (Next, M) — 보는 것**

- **미리보기 모달**: 실제로 보낼 프롬프트 본문을 그대로(치환 적용 후) 보여준다. 스크롤 + 검색 + '전체 복사'
- **마스킹 규칙**: 치환 목록(`SUDA → 플랫폼A`)
- **전송 이력**: `store` 신규 테이블 `egress(run_id, ts, provider, model, chars, sessions, repos_json, excluded_json)` + 설정 › 정보에 표 + CSV 내보내기

#### 화면 흐름 (N0)

```
[설정 › AI 요약]
  ⓘ 요약을 만들 때 세션 질답 · 커밋 메시지 · 회의 제목 · 메모가 Claude 로 전송됩니다.
     그 외에는 아무것도 나가지 않습니다.

[설정 › 수집 소스]
  제외할 저장소 · 폴더            (글롭 지원 · 요약 프롬프트에서 빠집니다)
  ┌──────────────────────────────────────┐
  │ D:\works\a-corp\**                   │  [−]
  │ D:\works\payments-core               │  [−]
  └──────────────────────────────────────┘  [+ 추가]

[오늘 화면]
       [ 지금 일지 만들기 ]
  제외 2곳(a-corp, payments-core) — 이 항목은 요약에 포함되지 않습니다
```

## 7. 지표(KPI)

### 7-1. (A) 지금 내 PC 에서 관측 가능한 지표

**로컬 전용 원칙을 깨지 않는다.** 자동 텔레메트리 서버를 세우지 않는다. `store.rs` 의 `runs` · `documents` · `notes` · `kv` 는 이미 원시 데이터를 갖고 있다. 집계 뷰만 추가하고, 설정 › 정보에 **"내 사용 통계"** 로 사용자에게 먼저 보여준다.

| # | 지표 | 정의 · 산출식 | 출처 | 현재 | 4주 목표 |
|---|---|---|---|:--:|:--:|
| **M1** | **불가능 지표 발생률** | 프로젝트 집중 합계 > 24h 인 문서 비율. **생성 시 결정론적으로 검증** | 검증 로그 | 100%(샘플) | **0%** |
| **M2** | **세션 중복률** | (롤업 세션 수 − distinct `session_id` 수) ÷ distinct 수 | 검증 로그 | 발생(샘플 3중복) | **0%** |
| **M3** | **시스템 문구 포함 문서 비율** | 타임라인 제목에 차단 패턴이 남은 문서 | 검증 로그 | 100%(샘플) | **0%** |

**대표 지표**: 초안은 **편집률**을 대표로 골랐다. **강등한다.** 같은 릴리스에 섹션 토글(초안 N3)이 들어가면 편집의 상당 부분("뒤쪽 섹션 지우기")이 설정으로 사라지고, **N1·N2 가 아무 효과가 없어도 편집률은 떨어진다.** 전형적인 Goodhart 다. 이번 개정에서는 ① 섹션 토글을 Now 에서 뺐고 ② 편집률을 **본문 영역 한정**(M5)으로 좁혔으며 ③ 대표 지표를 아래 둘로 바꾼다.

> **대표 지표 = M1(불가능 지표 발생률) + M4(근거 앵커 없는 성과 줄 비율).**
> 둘 다 n=1 에서도 참/거짓이 명확하고, 결정론적으로 100% 관측되며, 문서의 아래쪽 절반과 위쪽 절반을 각각 하나씩 지킨다.
