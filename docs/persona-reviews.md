## 1. 김지훈(34) · 핀테크 백엔드 6년차

### 프로필

저장소 6~8개를 worktree 로 오가며 Claude Code 와 Codex 를 하루 20~30세션 돌린다. 금요일 주간보고가 고역이라 이 앱을 찾았고, 노션 팀 위키 + 개인 Obsidian 을 쓴다. 설정은 만질 줄 알지만 "한 번 세팅하고 잊고 싶다". 화면보다 결과물(일지 텍스트)의 질이 최우선.

### 사용 의향

**★★★★☆ (4 / 5)**

### 첫인상

"오늘 뭐 했더라?"라는 README 첫 줄에서 바로 내 얘기라고 생각했다. 실제로 켜 두니까 진짜로 아무것도 안 해도 쌓인다 — 커밋도 아니고 지라도 아니고 내가 Claude/Codex 에 던진 질문이 하루의 뼈대가 된다는 발상이 제일 마음에 들었다. "수집은 자동, 문서는 수동"도 동의한다. 저녁 6시 반에 알림이 오면 그때 한 번 누르는 리듬이 딱 맞았다.

다만 2주 쓰고 나서 앱의 성격이 갈린다는 걸 알았다. 문서 앞쪽 절반(한 줄 요약 · 오늘의 성과 · 결정·요청·할 일 · 프로젝트별 진행)은 "이건 AX 맞네" 싶은 수준이고, 뒤쪽 절반(지표 · 프로젝트별 집중 · 타임라인)은 숫자가 틀리거나 남한테 못 보여줄 문구가 섞여 있어서 매번 내가 지우고 올린다. 그리고 결정적으로, 내가 이걸 깐 이유인 "금요일 주간보고"까지는 앱이 데려다주지 않는다. 하루 문서는 다섯 개 생기는데 한 주는 여전히 내가 손으로 합친다.

### 온보딩 (첫 5분)

설치 자체는 3분이면 끝난다. Releases 에서 `Worklog_<버전>_x64-setup.exe` 받아서, SmartScreen 경고에 `추가 정보` → `실행`(README 에 적혀 있어서 당황은 안 했다). WebView2 는 이미 있었다.

**막힌 곳**

1. **첫 실행에 아무 안내가 없다.** 창이 뜨면 바로 '오늘' 빈 화면이고 "아직 수집된 활동이 없어요 / 실시간 감시가 켜져 있어요 — 세션·커밋은 저절로 나타납니다" 뿐이다. 뭘 먼저 설정해야 하는지, 지금 뭘 하고 있는지(첫 스캔 중인지)는 화면에 안 나온다.
2. **기본값이 "모든 고정 디스크" + 탐색 깊이 5단계다.** 회사 노트북 C·D 를 통째로 훑는다는 말인데 그걸 켜기 전에 물어보지 않는다. 다 끝나고도 "저장소 몇 개 찾음" 같은 결과 표시가 없어서 잘 된 건지 확인이 안 된다. 나는 결국 '지정한 폴더'로 바꿔서 `D:\study`, `D:\works` 만 넣었다 — 그게 훨씬 빨랐다.
3. **5분 안에 못 끝나는 건 회의다.** NaverWorks 는 Client ID · Client Secret · Service Account · Private Key(PEM) · 사용자 ID 를 다 넣어야 하고, 그 전에 developers.worksmobile.com 에서 앱 등록하고 `calendar.read` 승인을 받아야 한다. 이건 하루 이틀짜리 사내 승인 건이다. 첫날은 git + Claude + Codex 만으로 시작했다.
4. **좋았던 것**: AI 요약 탭에서 "claude CLI 찾음 · <경로>" 가 떠 있었다. API 키를 안 넣어도 된다는 게 첫날 허들을 확 낮췄다. 반대로 모델 칸에 `claude-opus-4-8` 같은 문자열이 기본으로 박혀 있어서(칸 설명은 "비우면 CLI · API 의 기본 모델"), 이게 내 계정에서 되는 모델인지 아닌지 몰라 한참 들여다봤다. **이건 비워두는 게 맞지 않나 싶다.**

### 하루 루틴

**수집** — 진짜 손이 안 간다. 트레이에 떠 있고 '오늘' 헤더에 "실시간 감시 중 · 마지막 이벤트 17:44" 가 살아 있어서 켜져 있다는 걸 안다. 세션 저장하고 몇 초 뒤에 피드에 뜬다.

**메모** — `Ctrl+Shift+Space` 로 뜨는 빠른 메모 창이 이 앱에서 제일 잘 만든 부분이다. "구두 요청 · 결정 · 할 일 — #태그 @이름" 한 줄 치고 Enter 하면 닫히고, 다음에 열면 "16:02 저장됨 · …" 로 들어간 걸 보여준다. 한글 조합 중에 Enter 쳐도 안 튄다(이거 은근히 다른 앱들 다 틀린다). 회의 중에 팀장이 던진 요청을 알트탭 없이 박아넣을 수 있어서, 2주 동안 메모 30개쯤 쌓였다.

**불편한 건 피드 자체다.** 나는 하루 20~30세션이라 피드가 세션 카드로 도배된다. 필터가 '전체 / 메모만' 두 개뿐이라 "커밋만" 이나 "이 프로젝트만" 은 못 본다. 그리고 세션 한 건이 "08:36–14:27 · 진행 중" 처럼 6시간짜리 한 줄로 앉아 있는 경우가 많아서(창 열어두고 점심 다녀오면 그렇게 된다) 타임라인이 실제 하루 모양과 다르다.

**저녁** — 18:30 에 "9월 16일 일지를 만들 시간입니다" 배너가 뜨고, '지금 일지 만들기' 누르면 수집 → 요약 → 저장 3단계가 보이면서 "보통 2–3분" 이라고 알려준다. "창을 닫아도 트레이에서 계속됩니다" 도 좋고, 생성 중에 메모하면 "지금 추가한 메모는 다음 생성에 반영됩니다" 라고 알려주는 것도 정직해서 마음에 든다. 끝나면 '일지' 화면으로 알아서 넘어간다. 여기까지는 흠잡을 게 없다.

**문제는 그 다음이다.** 나는 일지를 그대로 안 쓴다. 매번 '편집'으로 들어가 뒤쪽 지표·타임라인을 지우고 노션에 올린다. 그러면 "편집됨" 이 되고, 다음에 다시 만들려면 확인 창을 한 번 더 거친다. 즉 **매일 손이 두 번 더 간다.** 2주 중 4일은 그냥 귀찮아서 '보고용' 템플릿으로만 뽑았다.

### 일지 품질

샘플(2026-09-16 표준 템플릿)을 실제 내 하루라고 치고 읽었다. 앞쪽은 기대 이상, 뒤쪽은 그대로는 못 쓴다.

**그대로 복붙 가능한 부분**

- **한 줄 요약**: "> SUDA MCP 플랫폼 인증 방향 확정·리뷰 반영과 KMS 아카이빙 알림 워크플로우 설계·생성을 마무리하고, KMS 엑셀 청킹 실패의 근본 원인을 규명한 하루." — 주간보고 한 줄로 그냥 쓴다.
- **오늘의 성과가 `[프로젝트]` 태그로 시작하는 것**: "[agent_platform_file] KMS 엑셀 청킹 실패 근본 원인 규명 — max_tokens 잘림 응답의 6회 재시도 루프가 근인, 2026-03-06 커밋 기점으로 특정". 내가 쓰는 말보다 낫다. 파일명·라인(`llm.py:424/578`, `OpensearchService.java:227`)까지 살려주는 건 놀랐다.

**못 쓰는 부분**

- **지표 한 줄**: "커밋 **0** (+0/−0) · 저장소 0 · AI **30세션**". 저장소를 6~8개 오가는 사람한테 "저장소 0" 은 그 자체로 앱이 고장 난 것처럼 보인다. 그날 진짜 커밋이 없었던 건지, 못 찾은 건지 문서만 봐서는 구분이 안 된다.
- **프로젝트별 집중 표**: agent-platform-backend **23h 32m**. 하루는 24시간이다. 세션 20개의 (마지막−처음)을 그냥 더한 값이고, worktree 마다 같은 세션이 3번 잡히고, 점심시간·회의시간도 다 들어간다. 이 표가 있는 한 이 문서는 팀장한테 못 보낸다. 오히려 "얘 하루에 23시간 일했다고 보고하네" 소리 듣는다.
- **타임라인(접힌 부분)**: `<recommended_plugins>\nHere is a list of plugins that are available but`, "The following is the Codex agent history whose request action you are" 같은 프롬프트가 4~5번 중복, 그리고 내 반말 첫 마디가 그대로 제목이 된다 — "해봐", "보통 이런식으로 만들기도 하는거야 근데?". `<details>` 로 접혀 있으니 괜찮다고 생각하면 안 된다. **노션에 넣으면 펴진 채로 올라간다.**
- **회의 제목이 원문 그대로 나간다**: "[HAI본부] 알파팀 2기 진행 결과 발표", "개발팀 스테이지 배포". 내 개인 일지면 괜찮은데 팀 위키에 올릴 문서엔 그대로 실리면 곤란한 날이 있다.

**템플릿**

표준/보고용/회고용 3종은 좋은 선택이다. 팀장한테 보낼 땐 '보고용'(성과 + 결정·요청 + 지표 한 줄)이 딱이다. 다만 그 '지표 한 줄'에 "커밋 0 · 저장소 0" 이 박혀 나가서, **제일 짧은 템플릿이 제일 안 좋은 인상을 준다.** 그리고 내가 직접 적은 메모가 문서에서 어느 줄인지 구분이 안 된다 — 메모는 내가 책임지는 1차 사실이고 나머지는 AI 추론인데, 결과물에서 둘이 똑같이 생겼다.

### 설정

저장 버튼이 없고 "변경 즉시 저장됨 · 18:41" 이 머리글에 뜨는 방식, 이거 좋다. 설정 만지다가 저장 안 눌러서 날리는 일이 없다. 탭 6개(자동화 · 모양 · 수집 소스 · 저장 대상 · AI 요약 · 정보) 구성도 납득된다. '자동화' 는 진짜 한 번 세팅하고 잊었다: 시각 18:30, 요일 월~금 칩, 동작 '알림만'. "회의 확인·전체 재수집 주기는 실시간 수집을 꺼도 계속 돕니다" 같은 한 줄 설명이 곳곳에 있어서 헷갈릴 일이 적었다.

**불만은 노브의 방향이다. 있는 건 내가 안 만질 것들이고, 내가 만지고 싶은 건 없다.**

- **안 만지는 것**: "질답 상한 … 120턴 / 180자", "파일 행 상한 200000행", "긴 날 처리 … 20000자 이상이면 세션별 압축 / 4 병렬". 이게 일지 품질을 어떻게 바꾸는지 설명이 없으니 손대면 손해 볼 것 같아서 그냥 둔다. 개발자인 나도 안 만지는데 일반 사용자는 더 그럴 거다.
- **만지고 싶은데 없는 것**: (a) 특정 저장소/프로젝트를 일지에서 빼기, (b) 같은 프로젝트의 worktree 를 하나로 합치기, (c) 세션 제목을 첫 발화 말고 다른 걸로 뽑기, (d) 타임라인/집중 표를 문서에서 빼기(템플릿을 바꾸는 것 말고 섹션 단위로).
- '모양' 탭(테마·글꼴·글자 크기)은 솔직히 나한텐 우선순위가 아니다. 이 탭에 들인 공의 절반이 '수집 소스 제외 규칙'에 갔으면 더 좋았을 것 같다.
- **사소한 것**: '저장소 다시 찾기' 를 눌러도 "저장소를 다시 찾는 중…" 토스트만 뜨고 몇 개를 찾았는지 결과가 안 보인다.

### 신뢰 · 프라이버시

핀테크라 이 항목이 제일 예민하다. 결론부터: **로컬 우선 설계는 믿음이 가는데, "무엇이 밖으로 나가는지" 를 내가 통제할 수 없다는 게 걸린다.**

**좋은 점**

- "전부 로컬에서 동작한다. 요약을 쓸 때만 Claude 로 나간다"(README) 는 정직한 문장이고, 실제로 데이터도 `~/.worklog/worklog.db` 와 문서 폴더에만 있다. 호스팅형 서버가 없다는 게 사내 반입 심사에서 제일 큰 장점이다.
- claude CLI 로그인을 그대로 쓰는 것도 좋다. API 키를 하나 더 만들어 노트북에 두지 않아도 된다.
- AI 요약을 '사용 안 함(데이터만 정리)' 로 둘 수 있는 선택지가 있다는 것도 안전판이다.

**걸리는 점**

- **나가는 내용을 고를 수 없다.** 샘플만 봐도 사내 서비스명(SUDA, KMS), 사내 조직/호칭(의장님, 계열사, HAI본부), 내부 파일 경로, Traceback 원문이 그대로 세션 질답에 실려 요약 프롬프트로 나간다. 저장소별 제외 목록도, 마스킹도, "이번에 이만큼 나갑니다" 미리보기도 없다. 회사 규정상 특정 저장소는 아예 빼야 하는데 방법이 없어서, **나는 그 프로젝트를 하는 날엔 앱을 껐다.** 그게 이 앱이 원하는 사용법은 아닐 거다.
- **비밀값이 평문이다.** `~/.worklog/settings.json` 에 NaverWorks client secret 과 private key PEM, Notion 토큰이 그대로 들어간다. 화면에서 "설정됨 · 바꾸려면 입력" 으로 안 보여주는 건 잘한 건데, 파일 자체는 백업·동기화에 그대로 딸려간다.
- **설치기에 코드 서명이 없는데 자동 업데이트가 켜져 있다.** 사내 PC 에 "서명 없는 exe 가 스스로 새 버전을 받아 설치한다" 를 보안팀에 설명하기 어렵다.
- **보관 정책이 없다.** 하루 스냅샷이 SQLite 에 계속 쌓이는데 '정보' 탭에는 '폴더 열기' 뿐이고, "90일 지난 기록 지우기" 나 "전부 삭제" 버튼이 없다.

### 첫인상

첫인상은 좋았어요. 창 띄우자마자 왼쪽 레일에 '오늘 · 일지 · 설정' 세 개뿐이라 뭘 눌러야 할지 헤맬 일이 없고, 손그림 테두리에 메모가 노란 스티커로 붙는 게 진짜 귀여워요. 무거운 회사 툴 느낌이 아니라 다이어리 같아서 "이건 좀 쓰겠다" 싶었습니다. 오늘 화면 맨 아래 입력창이 카톡처럼 생긴 것도 좋았고요("구두 요청 · 결정 · 할 일을 적어두세요").

### 온보딩 (첫 5분)

**5분 안에 "오, 되네"가 안 나왔어요.** 정확히는 딱 하나만 나왔습니다.

- 처음 뜬 화면은 빈 피드 + "실시간 감시가 켜져 있어요 — 세션·커밋은 저절로 나타납니다. '지금 갱신'으로 바로 확인할 수도 있어요". 안내는 이 한 줄이 전부고 첫 실행 가이드나 설정 마법사가 없어요. '지금 갱신'을 눌렀는데 뭘 훑고 있는지는 안 보이고(기본이 '모든 고정 디스크' + 탐색 깊이 5단계라는 건 나중에 설정에서 알았어요), 제 커밋이 잡힌 건 그날 오후 push 하고 나서였습니다.
- 그 상태에서 궁금해서 '지금 일지 만들기'를 눌렀어요. 생성 카드가 '수집 → 요약 → 저장 · 로컬 md' 로 뜨는 건 예뻤는데("보통 2–3분"), 30초쯤 뒤 알림이 **"저장했습니다(AI 요약 없음)"** 였습니다. 제 노트북엔 claude CLI 가 PATH 에 없었던 거예요. 근데 그 사실은 설정 › AI 요약 탭까지 들어가서 "claude CLI 를 찾지 못했습니다" 를 봐야 알 수 있어요. 첫 5분에 그 탭을 왜 들어가겠어요. 만들어진 일지는 "> LLM 요약을 사용하지 않았습니다. 아래 지표를 참고하세요." 로 시작하는, 표 하나짜리 문서였고요. **이게 제 첫 결과물이었습니다.**

정리하면 **설치는 쉬운데 '첫 성공'이 운에 맡겨져 있어요.** claude CLI 가 깔린 사람은 3분 만에 감동하고, 저 같은 사람은 빈 문서 받고 끝납니다.

### 하루 루틴

**수집** — 진짜 자동이라는 건 인정해요. 켜 두면 커밋이 알아서 올라오고, Claude Code 켠 날은 세션이 '진행 중 · 마지막 활동 16:12' 로 살아 움직이는 게 재밌어요. 근데 **제 하루의 절반은 회의인데 그게 안 들어와요**(NaverWorks 를 못 붙였거든요). 그래서 피드가 "커밋 3 · AI 세션 1 · 회의 0" 인데 실제로는 회의 3개에 코드리뷰만 하다 끝난 날이 많았고, 그런 날은 화면이 거의 비어 있어서 "나 오늘 논 건가" 싶어 기분이 좀 나빴어요. **정작 그런 날이야말로 기록이 필요한 날인데요.**

**메모** — 제일 좋았던 부분. `#요청 #결정 #할일 #회의` 칩을 누르면 입력창에 붙고 "@이름 으로 요청자 표시" 라고 안내해 줘서, 팀장님이 지나가며 말한 걸 `#요청 @이팀장 로그인 화면 에러문구 바꿔주세요` 로 던져두는 게 습관이 됐어요. 수정·삭제도 행에서 바로 되고요. 2주 중 메모만큼은 한 번도 안 빼먹었습니다.

**생성** — '지금 일지 만들기'는 하루 한 번 눌렀어요. 진행 카드에 "창을 닫아도 트레이에서 계속됩니다" 라고 써 있어 안심하고 창 닫는 게 좋았고, 끝나면 '일지' 화면으로 알아서 넘어가는 것도 마음에 들어요.

**정해진 시각** — 기본이 평일 18:30 알림만이라 첫날 퇴근길에 "일지를 만들 시간입니다" 배너가 떴어요. 부담 없어서 좋았는데, 야근하다 놓친 날은 그냥 넘어가고 다음날 아침에 "(꺼져 있던 동안 지난 알림)" 이 붙어 뜨더라고요. 근데 이미 어제 일이라 그때 만들면 늦었다는 기분이 들어요. 그리고 상단에 "18:30 일지 알림 켜짐" 필이 늘 떠 있는데, 저는 이게 '자동으로 만들어 주는 중' 인 줄 착각해서 **이틀 정도 일지를 안 만들었습니다.**

**지난 날짜** — 이건 칭찬. `‹` `›` 로 어제로 가면 "지난 날짜 · 저장된 기록 · 18:42 갱신" 이 뜨고, 그 날짜로 메모를 남기면 "9월 15일 기록으로 저장됩니다" 라고 알려줘요. 깜빡한 날을 나중에 채울 수 있다는 게 저 같은 작심삼일형에게는 중요해요.

### 일지 품질

**좋은 것**

- 맨 위 한 줄 요약이 있고 바로 `## 오늘의 성과` 가 `[agent-platform-backend]` 처럼 프로젝트 태그로 시작해서, 금요일 주간보고에 그대로 복붙할 수 있게 생겼어요.

**못 쓰겠는 것 — 남한테 보여줄 수가 없어요**

- 접힌 타임라인을 열었더니 제 프롬프트가 날것 그대로 있어요. `🤖 보통 이런식으로 만들기도 하는거야 근데? · agent-platform-backend` 같은 반말 혼잣말이요. 저는 Claude 한테 "이거 왜 안 되냐고요ㅠㅠ" 같은 말도 하는 사람인데, 그게 일지에 박혀서 Obsidian·Notion 으로 자동 저장된다는 게 좀 무서웠어요.
- 아예 제 말이 아닌 것도 섞여요. `<recommended_plugins>`, `The following is the Codex agent history…`, `Traceback (most recent call last): File "/app/app/services/KmsUpload…` 같은 시스템 문구랑 붙여넣은 에러 로그가 '세션 제목' 자리에 앉아 있어요. **사람이 읽는 문서가 아니라 로그 덤프 같아요.**

**제 용도(성장기록·회고) 기준으로는** 표준 템플릿보다 회고용이 맞아요. `막힌 것 · 배운 것` 섹션이 딱 제가 쓰고 싶은 거예요. 근데 기본이 표준이라, 설정 › AI 요약 › 일지 템플릿까지 들어가야 그런 게 있는 줄 알게 돼요. **저는 2주째에 발견했습니다.**

### 설정

탭이 여섯 개인데 제가 끝까지 본 건 두 개예요.

**괜찮았던 곳**

- 저장 버튼이 없는 게 처음엔 "어 저장 안 했는데?" 싶었는데, 머리글에 "변경 즉시 저장됨 · 18:41" 이 뜨니까 금방 믿게 됐어요.

- **저장 대상**: Notion 쪽의 "대상 종류(페이지/데이터베이스)", "제목 속성", "API 버전 2022-06-28" 에서 또 닫았어요. 로컬 md 는 기본으로 켜져 있어서 다행이었습니다.

"로컬에서 돈다" 는 말은 믿음이 가요. 근데 2주 쓰고 나니 애매한 지점들이 보여요.

### 첫인상

README 첫 줄 "오늘 뭐 했더라?"에서 바로 설득당했다. 금요일 저녁마다 내가 하는 짓이 정확히 그거다. 원칙도 마음에 들었다 — "수집은 자동, 문서는 수동". 내가 자리를 비운 사이에 AI 가 멋대로 내 이름으로 문서를 쓰고 있는 건 싫으니까.

그런데 앱을 켜자마자 위쪽에 뜬 숫자가 "커밋 · AI 세션 · 회의 · 메모" 이 순서다. **내 하루로 채우면 앞의 두 칸은 대부분 0 이다.** 2주 동안 커밋 0 인 날이 6일이었고, 그런 날 오늘 화면은 "0 커밋 / 0 AI 세션 / 3 회의 / 5 메모" 였다. 이 앱은 하루 종일 코드를 치는 사람의 하루를 전제로 만들어졌구나, 를 첫 화면에서 알았다.

한 줄로: **컨셉과 메모 입력은 내 문제를 정확히 겨눴는데, 지표와 결과물은 아직 '코딩하는 사람의 하루'를 보고 있다.**

### 온보딩 (첫 5분)

설치 자체는 5분 안에 됐다. 다만 5분 안에 '쓸 만해지지는' 않았다.

1. **설치기**: SmartScreen 경고가 떴고 `추가 정보` → `실행` 으로 넘겼다. 나야 넘기지만, **팀원 7명에게 이걸 시키는 건 완전히 다른 얘기다.** 첫 관문에서 이미 '팀 배포'는 접어뒀다.
2. **첫 실행**: git 기본값이 "모든 고정 디스크" + 탐색 깊이 "5단계" 였다. 뭘 훑는지 물어보지도 않고 내 디스크를 다 돈다. 회사 PC 에 개인 토이 저장소도 섞여 있는데 그게 그대로 후보가 된다. **첫 실행에서 "어디를 볼까요?"를 한 번만 물어봤으면 훨씬 안심했을 것이다.**
3. **회의 연결이 진짜 벽이었다.** 내 하루의 대부분이 회의인데, 그걸 넣으려면 일곱 칸을 다 채우고 앱 등록 + `calendar.read` 승인을 따로 받아야 한다. 이건 5분이 아니라 '보안팀 요청서 한 장'이다. 2주 중 첫 3일은 회의가 아예 안 들어온 채로 썼고, 그동안 이 앱은 나에게 반쪽이었다.
4. **AI 요약** 탭에서 "claude CLI 찾음" 이 떠서 나는 통과. 그런데 모델 칸에 `claude-opus-4-8` 이 이미 적혀 있고 옆 힌트는 "비우면 CLI · API 의 기본 모델" 이다. **채워져 있는데 비우라니, 이건 손대야 하는 건지 아닌지 끝까지 몰랐다.**
5. **정말로 5분 안에 된 것**: 앱 켜고 메모 한 줄 적기. 이게 없었으면 2주를 안 버텼다.

### 하루 루틴

**모으기** — 내 쪽에서 자동으로 모이는 건 사실상 회의뿐이다. 커밋은 드물고 Claude 세션도 리뷰할 때 잠깐이다. 그래서 **내 하루 일지의 재료는 9할이 내가 직접 친 메모다.** 앱은 '자동 수집'을 주인공으로 두고 메모를 곁들이로 뒀는데, 나 같은 사람에겐 정반대다.

**메모** — 여기는 정말 잘 만들었다. 아래 입력창 안내가 "구두 요청 · 결정 · 할 일을 적어두세요" 이고, `#요청 #결정 #할일 #회의` 칩을 누르면 입력에 붙고 "@이름 으로 요청자 표시" 라고 옆에 적혀 있다. 내가 원하던 문법이 그대로 있다. Enter 저장 / Shift+Enter 줄바꿈도 손에 붙었다. 노란 스티커로 보이는 것도 자동 수집 항목과 안 섞여서 좋다.

**빠른 메모** — `Ctrl+Shift+Space` 로 어디서든 한 줄. 회의 중에 노트북을 열어두는 날은 최고였다. **문제는 회의실에 폰만 들고 들어가는 날이다.** 자리에 돌아와서 적으면 그 시각으로 박힌다. 게다가 빠른 메모 창은 '오늘'로만 들어간다.

**지난 날짜** — 오늘 탭에서 `‹` `›` 로 어제로 가서 적으면 "9월 16일 기록으로 저장됩니다" 라고 알려준다. 여기까지는 훌륭하다. 그런데 **시각은 '지금'이 들어간다.** 어제 10시 회의 메모를 오늘 저녁에 적으면 어제 18:4x 로 꽂혀서 타임라인 순서가 뒤집힌다.

**만들기** — "보통 2–3분" 이라고 뜬다. 퇴근 직전 2~3분은 은근히 길다. 대신 "창을 닫아도 트레이에서 계속됩니다" 가 있어서 눌러놓고 나가면 된다는 걸 알고 나서는 괜찮아졌다.

**정해진 시각** — 기본이 평일 18:30 알림만이다. **나는 그 시각에 회의 중인 날이 절반이다.** 알림을 놓친 날은 일지가 안 만들어지고, 일지가 없으면 그날 메모는 검색에도 안 걸린다(일지 화면 검색은 만들어진 문서를 뒤진다). 즉 **'문서를 안 만든 날 = 기록이 없는 날'이 되는 구조**라, 수동 생성 원칙의 대가를 내가 치른다.

**2주 결산**: 메모 입력은 습관이 됐고(하루 4~8건), 일지 생성은 9일 했다. 못 만든 날 5일은 지금도 메모로만 남아 있고 찾아 쓰기가 어렵다.

### 일지 품질

샘플(표준 템플릿)을 내 기준으로 보면, **위쪽 절반은 쓸 만하고 아래쪽 절반은 못 쓴다.**

**좋은 것**

- "오늘의 성과"가 `[agent-platform-backend] MCP 서버 인증 방향 확정(OAuth+PAT 2갈래, B안)…` 처럼 프로젝트 태그로 시작한다. 주간보고에 그대로 옮겨 붙일 수 있는 문장이다. **이건 내가 손으로 만들던 형식과 같다.**
- "결정 · 요청 · 할 일"이 `결정:` / `요청(@이름):` / `- [ ]` 로 딱 갈라져 있다. 세 템플릿 모두 이 두 섹션을 공통으로 둔 것도 설계가 제대로다.
- "프로젝트별 진행"의 각 줄 끝에 (완료)/(진행 중)/(막힘) 이 붙는다. **본부 보고에서 제일 먼저 묻는 게 그거라 유용하다.**

**못 쓰는 것**

- **집중시간 표의 `agent-platform-backend 23h 32m`.** 하루는 24시간이다. **숫자 하나가 터무니없으면 위의 잘 쓴 문장들까지 같이 의심받는다.**
- **접힌 타임라인의 내용.** `<recommended_plugins>`, `The following is the Codex agent history…`, `Read D:\study\ai-web-novel\docs\…` 같은 시스템 문구와 내부 경로가 그대로 있고, 같은 세션이 `08:36–14:27` 두 줄, `13:06–13:13` 네 줄로 중복돼 있다.
- **내 말이 그대로 노출된다.** `보통 이런식으로 만들기도 하는거야 근데?`, `10초 안에 응답 나와?` 가 제목으로 박혀 있다. 이게 Notion 에 올라가고 누가 펼쳐 본다. **팀원에게 쓰라고 권했다가 이 줄 때문에 원망 들을 자신이 있다.**
- **지표 줄이 내 것이 아니다.** 본부 보고에서 '출력 1.3M토큰'은 의미가 없다. 내가 필요한 건 **회의 시간 합계, 처리한 요청 건수, 미해결 할 일 수**다.
- **주간이 없다.** 템플릿 3종이 전부 하루짜리다. 내가 진짜 필요한 건 월~금 다섯 장에서 '오늘의 성과'와 '결정·요청·할 일'만 뽑아 합친 초안 한 장인데, 그걸 지금도 내가 손으로 복사하고 있다.
- **할 일이 이월되지 않는다.** 어제 `- [ ]` 로 남긴 게 오늘 문서 어디에도 안 나온다. **매일 새 종이다.**

정리하면, 이 일지는 **'내가 오늘 뭐 했는지 나 혼자 확인하는 용도'로는 4점, '남에게 보내는 문서'로는 2점**이다.

### 설정

구조는 좋다. 탭 6개로 나뉘어 있고 각 탭 부제("수집은 자동으로, 일지 작성은 원할 때")가 그 탭에서 뭘 정하는지 말해준다. 오른쪽 위 "변경 즉시 저장" 표시 덕에 저장 버튼을 찾아 헤맬 일이 없다. 비밀값 칸이 "설정됨 · 바꾸려면 입력" / "비우면 현재 값 유지" 로 동작하는 것도 제대로 만들었다. "최근 생성" 표에 실패 원인과 '다시 시도'가 있는 것도 좋다.

**불편한 것**

- **수집 소스 탭이 개발자 언어다.** "질답 상한 … 세션당 120턴 / 답변 180자", "파일 행 상한 200000행", "긴 날 처리 … 20000자 이상이면 세션별 압축 / 4 병렬", "최대 토큰 4000". 이 숫자들을 올리면 일지가 좋아지는 건지 비용이 늘어나는 건지 나조차 모르겠어서 2주 동안 한 번도 안 건드렸다. **우리 팀 PM 에게 이 화면을 주면 손도 못 댄다.**
- **팀에 뿌릴 방법이 없다.** 설정 내보내기/불러오기가 없어서 7명에게 같은 설정을 깔아주려면 각자 NaverWorks 값 여섯 칸을 손으로 치게 해야 한다. `settings.json` 을 복사해 주면 되긴 하는데 README 가 "비밀값이 들어 있으니 공유 금지" 라고 못 박았다 — 맞는 말이고, 그래서 배포 경로가 막힌다.
- **백업/이관이 없다.** PC 를 바꾸면 2주치 메모가 어떻게 되는지 앱이 말해주지 않는다.
- "앱 종료" 확인 문구("종료하면 실시간 수집과 정해진 시각 알림도 멈춥니다")는 친절했다. **이런 문장이 다른 곳에도 더 있으면 좋겠다.**

### 신뢰 · 프라이버시

**여기가 내가 팀 도입을 못 밀어붙인 진짜 이유다.**

앱이 잘한 것부터. README 가 "전부 로컬에서 동작한다. 요약을 쓸 때만 Claude 로 나간다"를 앞쪽에서 말한다. 계획 문서에도 "로컬 전용 데스크톱 앱. 호스팅형 웹 없음" 이라고 적혀 있다. AI 요약 탭에 "사용 안 함 (데이터만 정리)" 선택지가 실제로 있고, Claude Code 세션·Codex 세션을 각각 끌 수 있다. **태도는 분명하다.**

그런데 켜면(그게 기본이다) 내 Claude·Codex 세션 질답이 요약 프롬프트로 나간다. 그리고 **무엇이 나가는지 보여주는 화면이 없다.** 설정에 있는 건 "세션당 120턴 · 답변 180자" 같은 상한값뿐이다. 샘플 일지 타임라인에 `/app/app/services/KmsUploadService.py` 같은 사내 파일 경로와 Traceback 이 그대로 들어온 걸 보면, 프롬프트에는 그보다 더 들어갔을 것이다. **보안 검토 자리에서 "무엇이 나갔습니까"를 물으면 나는 답할 근거가 없다.** 지금 내가 쓸 수 있는 보호 수단은 '소스를 통째로 끄기' 하나뿐인데, 끄면 앱을 쓸 이유가 사라진다.

필요한 건 세 가지다. **(1) 생성 직전 "이번 요약에 나가는 내용 보기", (2) 저장소·폴더·경로 단위 제외 목록, (3) 언제 무엇을 얼마나 보냈는지 남는 기록.** 하나도 없다.

그리고 배포 쪽. 코드 서명이 없어 SmartScreen 경고가 뜨고, 업데이트는 공개 GitHub 저장소에서 앱이 알아서 받아 설치한다. **사내 PC 7대에 "서명 없는 설치기 + 공개 저장소 자동 업데이트"를 깔자고 보안팀에 말할 자신이 없다.** 마지막으로 `settings.json` 에 private key 와 Notion 토큰이 평문으로 들어 있다 — 회사 백업 정책이 그 폴더를 포함한다는 걸 내가 안다.

**결론**: 내 PC 한 대에서 내 메모를 정리하는 데는 쓴다. 팀에 뿌리는 건 위 세 가지가 생기기 전까지 보류다.

### 첫인상

"오늘 뭐 했더라?" 이 한 줄 보고 바로 설치했어요. 저녁마다 제가 하는 말이거든요. 근데 README 스크롤을 조금만 내리면 분위기가 확 바뀌어요. "무엇을 하나" 첫 줄부터 "git 커밋", 두 번째가 "Claude Code · Codex 세션", 세 번째가 되어서야 "NaverWorks 회의"예요. **제가 하루에 하는 일 중에 여기 있는 건 회의 하나고, 그마저 맨 아래예요.** 아래로 더 내려가면 "CLI (개발자용)", "요구 사항: Rust stable · Node 22 · pnpm 9" 같은 게 나오고요.

앱 자체는 정말 예뻐요. 손그림 느낌에 둥근 글씨체, 노란 스티커 메모, 오른쪽 아래 말풍선 입력창. 화면만 보면 "일기 앱" 같아서 좋았는데, **그 예쁜 껍질 안에 개발자 전용 엔진이 들어 있는 느낌이에요.** 첫인상을 한 문장으로 하면 "개발자 친구가 자기 쓰려고 만든 걸 예쁘게 포장해 준 앱".

### 온보딩 (첫 5분)

설치부터 마음이 한 번 꺾여요. 다운로드가 GitHub Releases라 화면이 온통 영어고 파일이 여러 개 나열돼요. 실행하니 파란 경고창. **회사 노트북에서 경고 무시하고 설치하는 건 저한텐 꽤 큰 결심이에요.**

**첫 5분이 진짜 문제였어요.**

- **1분**: 앱이 뜨고 '오늘' 화면. 가운데가 텅 비고 "아직 수집된 활동이 없어요 / 실시간 감시가 켜져 있어요" 라고 해요. **'감시'라는 말이 살짝 무섭고**, '세션·커밋'은 저한테 평생 안 생길 거예요.
- **2분**: 뭐라도 나오게 하려고 설정 → 수집 소스로 갔는데 맨 위가 "git 커밋"이고 켜져 있어요. 그 아래 "저장소 찾기: 모든 고정 디스크"가 눌려 있고 "탐색 깊이 5단계". 제 D드라이브를 통째로 훑는다는 뜻 같은데, **아무도 저한테 물어보지 않고 이미 켜져 있었어요.** 그다음이 "Claude Code 세션", "Codex 세션" — 둘 다 켜짐.
- **3분**: 맨 아래에 **제가 유일하게 필요한 "NaverWorks 회의"가 있는데 이건 꺼져 있어요.** 켜 봤더니 채워야 할 칸이 사용자 ID, Client ID, Client Secret, 서비스 계정, Private Key(PEM 붙여넣기), 키 파일, Scope. 여기서 끝났어요. 저 혼자서는 못 해요. **개발팀에 부탁하고 사흘 기다렸어요.**

첫 5분에 막히는 곳을 딱 집으면: **(1) 내가 필요한 소스는 꺼져 있고 안 필요한 게 켜져 있다, (2) 그 하나를 켜려면 개발자 계정 정보 일곱 칸이 필요하다, (3) AI가 기본으로 안 켜진다.** 세 개 다 "첫 실행 마법사"가 있었으면 1분에 끝날 일이에요.

### 하루 루틴

**수집** — 사실상 자동으로 들어오는 게 없어요. 개발팀이 회의 연동을 켜 준 뒤로는 캘린더 일정이 들어오기 시작했는데, 제 캘린더에 있는 건 대부분 "정기 스크럼" 같은 제목뿐이라 피드가 몇 줄로 끝나요. **위쪽 지표는 커밋 0, AI 세션 0, 회의 2, 메모 5. 숫자 넷 중 둘이 평생 0이에요.**

**메모** — 여기가 이 앱에서 제일 좋은 부분이에요. 아래 입력창 문구가 "구두 요청 · 결정 · 할 일을 적어두세요"이고, 위에 `#요청 #결정 #할일 #회의` 칩이 있어서 마우스로 톡 누르면 입력창에 붙어요. 회의 끝나고 자리로 오는 30초 동안 "#결정 결제 API 타임아웃 10초로 @김팀장" 한 줄 치는 건 정말 편해요. 노란 스티커로 쌓이는 것도 예뻐서 자꾸 쓰게 돼요. 트레이 메뉴의 '빠른 메모'도 좋아요 — 저는 단축키는 안 쓰고 트레이 아이콘을 눌러요.

다만 **결국 제 하루의 100%를 제가 손으로 친 거예요.** "AI가 귀찮은 일을 대신하고 사람은 판단만 한다"는 모토였는데, 제 경우엔 제가 다 치고 AI가 그걸 다시 요약해 주는 거라 "정리"는 되어도 "대신"은 아니에요. 그리고 **메모를 회의 항목에 붙일 수가 없어요.** 14시 회의 카드와 14시 05분에 쓴 메모가 그냥 시간순으로 나란히 있을 뿐이라, 나중에 "그 회의에서 뭐 정했지?"를 찾으려면 다시 눈으로 훑어야 해요.

**생성** — '지금 일지 만들기'는 마음에 들어요. 단계가 보이고 "18:42 시작 · 보통 2–3분", "창을 닫아도 트레이에서 계속됩니다"까지 알려 줘요. 기다리는 동안 뭘 하는지 보이니까 불안하지 않았어요.

**확인** — 넘어간 문서를 보면 제 메모들이 "결정: …", "요청(@김팀장): …", "- [ ] …"로 정리돼 있어요. **이건 진짜 쓸모 있어요.** 문제는 그 아래예요. 지표 줄에 "커밋 0 (+0/−0) · 저장소 0 · AI 0세션 · 출력 0토큰"이 매일 찍혀요. 0이면 안 보여 주면 될 텐데 회의·메모 건수만 0일 때 숨기고 커밋·세션은 항상 나와요. **매일 "너는 아무것도 안 했다"는 성적표를 받는 기분이라, 3일째부터는 문서 아래쪽을 아예 안 봤어요.**

### 일지 품질

샘플(표준 템플릿)을 처음부터 끝까지 읽었어요. 솔직하게 반반이에요.

**위쪽 절반은 정말 좋아요.** 맨 앞 한 줄 요약이 딱 정리돼 있고, '오늘의 성과'가 5줄, '결정 · 요청 · 할 일'에 "결정: …" 네 줄과 "- [ ]" 체크박스 세 줄이 있어요. **이 두 섹션만 있으면 저는 주간보고 한 칸을 채울 수 있어요.** 특히 결정과 할 일이 한군데 모여 있는 건 제가 지금 노션에 손으로 만들어 쓰는 표랑 똑같아요.

그런데 **내용이 전부 남의 언어예요.** "MCP 서버 인증 방향 확정(OAuth+PAT 2갈래, B안)", "max_tokens 잘림 응답의 6회 재시도 루프가 근인" — 제 하루가 이 앱을 통과하면 뭐가 나올까 상상해 보면, 회의 제목 두 개와 제가 친 메모 다섯 줄이 전부예요. **그 다섯 줄을 AI가 아무리 잘 다듬어도 제가 안 친 건 안 나와요.** 즉 이 앱이 잘하는 "자동 수집"의 재료가 저한텐 없어요.

**아래쪽 절반은 그대로 보면 좀 곤란해요.**

- '프로젝트별 집중' 표에 "agent-platform-backend … 23h 32m"이 찍혀 있어요. 하루는 24시간인데 한 프로젝트에 23시간 32분이요? **이 표를 팀장님한테 보여 줬다가 그 숫자부터 지적당할 게 뻔해요.**
- 접힌 '타임라인'을 펼치면 기계 문구가 제목 자리에 들어가 있어요. 같은 문구가 세 번 연속으로 나오기도 하고요. **이건 일지라기보다 로그 덤프예요.**
- '시간대별 흐름'은 잘 압축돼 있는데, 정작 제가 궁금한 "14:00 회의에서 뭐가 정해졌나"는 "14:00–15:00 회의: 개발팀 스테이지 배포" 한 줄뿐이에요. **회의는 있었다는 사실만 남고 알맹이가 없어요.**

정리하면 '오늘의 성과'와 '결정 · 요청 · 할 일'은 제 용도에 맞고, 나머지는 개발자 용도예요. '보고용' 템플릿이 제일 가까운데, 그 지표 한 줄도 "커밋 0 · 저장소 0 · AI 0세션"이라 결국 지우고 써야 해요.

**옮겨 붙이기.** '복사'를 눌러 노션에 붙이면 마크다운이라 그럭저럭 살아나는데, **파워포인트에 붙이면 "## 오늘의 성과", "- [ ]"가 글자 그대로 붙어요.** 노션 저장 기능은 "통합 시크릿", "대상 ID", "API 버전(2022-06-28)"을 넣어야 해서 포기했어요.

### 설정

설정은 여섯 탭이고 왼쪽에 이름이 쭉 있어서 찾기는 쉬워요. 저장 버튼이 없고 오른쪽 위에 "변경 즉시 저장됨 · 18:41"이라고 뜨는 것도 좋아요.

**'모양' 탭은 제가 제일 좋아하는 화면이에요.** 테마·글꼴·글자 크기가 칩으로 있고, 바로 아래 "업무일지 / 오늘 한 일을 적어두세요 · 가나다라 ABC 123" 미리보기가 눌러 보는 대로 바뀌어요. 아래에 "빠른 메모 창에도 같이 적용됩니다"까지 있어서 친절하고요. **이 탭은 정말 잘 만들었어요.**

**'자동화' 탭도 절반은 이해했어요.** "정해진 시각에 일지 챙기기 / 시각 18:30 / 요일 / 동작: 알림만 · 자동 생성"까지는 쉽고, 힌트에 풀어 준 게 좋았어요. 다만 "실시간 수집", "회의 확인 주기", "전체 재수집" 같은 말은 제 단어가 아니고, "회의 확인·전체 재수집 주기는 실시간 수집을 꺼도 계속 돕니다" 같은 안내는 **세 번 읽고도 무슨 뜻인지 자신이 없어요.** 왼쪽 레일 맨 아래 "시각 동작 꺼짐"도 무슨 뜻인지 한참 봤어요.

**나머지 탭은 저한테 외국어예요.** '수집 소스'의 "탐색 깊이", "질답 상한", "Scope", "Private Key". 'AI 요약'의 "최대 토큰", "긴 날 처리", "모델", "시간대". **이 두 탭은 "고급 설정"으로 접어 두고, 기본 화면에는 "무엇을 모을까요: 회의 / 메모 / (개발자면) 코드 작업" 정도만 있으면 훨씬 나을 것 같아요.**

**'정보' 탭은 필요한 게 다 있어요.** 버전, 폴더 경로에 '폴더 열기' 버튼, '업데이트 확인', 그리고 '앱 종료'를 누르면 확인해 줘요. 이런 확인 문구는 마음에 들어요.

### 신뢰 · 프라이버시

**불안한 쪽.**

- **'감시'라는 단어요.** "실시간 감시 중 · 마지막 이벤트 17:44"가 화면 위에 계속 떠 있어요. 단어가 감시라 누가 뒤에서 보면 오해할 것 같아요. **'모으는 중' 정도면 충분할 텐데요.**
- 회의 메모에는 인사 얘기나 아직 비공개인 일정도 들어가요. 그게 AI로 나간다는 건 README 한 줄로만 알 수 있어요. **정작 AI 요약 설정 화면에는 "무엇이 밖으로 나가는지"가 한 줄도 없어요.** '지금 일지 만들기' 누르기 전에 "오늘 메모 5건·회의 2건이 요약을 위해 전송됩니다" 같은 안내가 있으면 좋겠어요.
- 비밀번호 같은 값들이 그냥 파일에 들어간다는 것도요.

**안심되는 쪽.**

- 회원가입도 로그인도 없고, 데이터가 다 제 PC에 있다는 건 정말 좋아요.
- 비밀 값을 화면에 다시 안 보여 주고 "설정됨 · 바꾸려면 입력"으로만 표시하는 것도 잘한 것 같아요.
- 일지 끝에 원본을 붙이는 옵션이 기본 꺼짐인 것도 좋아요. 켜져 있었으면 제 메모 원문이 그대로 노션에 올라갈 뻔했네요.

## 5. 정하늘(38) · 1인 개발 프리랜서

### 프로필

클라이언트 3곳(A사 결제 모듈, B사 백오피스, C사 앱 API)을 동시에 돌리고, 매달 말일에 프로젝트별 작업 시간·내용을 정리해 청구서에 붙인다. 다크 모드·글자 크기 같은 세밀한 설정을 좋아하고, 작업 기록은 전부 Obsidian vault(`D:\notes\vault`)에 모아 Dataview 로 굴린다. **고객 코드가 내 PC 밖으로 나가는지에 특히 민감하다**(A사는 NDA에 AI 도구 사용 조항이 있다).

### 사용 의향

**★★★☆☆ (3 / 5)**

### 첫인상

README 첫 줄 "오늘 뭐 했더라?"에서 바로 걸렸다. 나도 매달 말일마다 커밋 로그랑 슬랙을 거슬러 올라가며 "이날 뭐 했지"를 재구성하느라 반나절을 쓴다. "기억이 아니라 데이터로"라는 말이 정확히 내 문제다. `docs/v2-plan.md §0` 에 "로컬 전용 데스크톱 앱. 호스팅형 웹 없음"이라고 박아둔 것도 마음에 들었다 — **이런 앱은 보통 "클라우드 동기화!"부터 자랑하는데 여긴 반대다.**

다만 2주 써보고 나서의 솔직한 결론은, **이 앱이 상정한 사용자는 "월급 받는 개발자의 주간보고"이지 "시간 단위로 돈을 청구하는 프리랜서"가 아니다.** 수집은 훌륭한데 집계가 없다. 하루짜리 문서는 잘 나오지만 그걸 한 달치로 합쳐주는 곳이 앱 어디에도 없고, 결국 나는 30개 일지를 열어서 표를 손으로 옮겨 적었다. 그 순간 모토에서 **제일 귀찮은 일이 나한테 남아 있다는 걸** 알았다.

### 온보딩 (첫 5분)

설치 자체는 2분. 다만 첫 5분에 세 번 멈칫했다.

1. **SmartScreen.** 내 PC야 내가 판단하면 되지만, **나는 클라이언트 사무실 PC에도 깔아야 할 때가 있다.** 거기 보안팀에 "서명 없는 exe인데 자동 업데이트도 됩니다"라고 설명할 자신이 없다.
2. **첫 실행에 안내가 없다.** 창이 뜨면 바로 '오늘' 피드고, 뭘 먼저 해야 하는지 말해주지 않는다. 나는 Obsidian 연결부터 하고 싶었는데 '저장 대상' 탭에서 Obsidian 이 기본 꺼짐(vault 경로 빈 칸)이라, 첫날 만든 일지는 그냥 `문서\업무일지` 에만 떨어졌다.
3. **제일 놀란 건 git 설정이었다.** '저장소 찾기'의 기본이 **모든 고정 디스크**(탐색 깊이 5단계)다. 내 D 드라이브엔 세 고객사 저장소가 다 들어 있고 E 드라이브엔 예전 고객 아카이브까지 있다. **첫 실행이 조용히 전 디스크를 훑고 있었다는 걸, 설정 탭에 들어가서야 알았다.** "지금 저장소를 찾는 중입니다 — 어디를 볼지 정하시겠어요?" 한 줄만 있었어도 훨씬 안심했을 것이다.

그리고 claude CLI 가 PATH 에 없으면 'AI 요약' 탭에 들어가야 경고를 본다. 나는 그 탭에 안 들어가 보고 첫날 '지금 일지 만들기'를 눌렀다가 알았다. **이건 첫 실행에서 먼저 말해줬어야 한다.**

### 하루 루틴

**여기가 이 앱의 제일 좋은 부분이다.** 2주 내내 트레이에 켜두고 아무것도 안 했는데 저녁에 열면 그날이 다 들어 있었다. "실시간 감시 중 · 마지막 이벤트 17:44" 처럼 시각까지 찍혀 나와서, 앱이 살아 있는지 의심할 일이 없었다.

**메모는 기대 이상이었다.** 빠른 메모 창의 입력 힌트가 "구두 요청 · 결정 · 할 일 — #태그 @이름" 이고, 저장하면 "17:42 저장됨 · …" 하고 방금 넣은 한 줄을 되보여준다. 전화로 "그거 다음 주까지 돼요?" 같은 소리를 듣고 바로 남기기에 딱이다. **이게 월말에 "이건 추가 요청이었다"를 증명하는 유일한 근거가 된다.**

**불편한 곳도 분명하다.**

- **태그 칩이 `#요청 #결정 #할일 #회의` 네 개로 고정이다.** 나한테 제일 중요한 태그는 **어느 고객 건이냐**인데, `#A사` 는 직접 타이핑해야 하고 칩으로 못 만든다. 그리고 태그를 아무리 성실하게 달아도 **태그별 집계 화면이 없어서** 결국 달아봐야 검색용이다.
- **피드에서 세션·커밋 행에는 프로젝트 이름이 굵게 붙는데, 메모 행에는 프로젝트가 없다.** "A사 건으로 30분 통화" 를 남겨도 그게 A사 시간으로 잡히지 않는다.
- '지금 일지 만들기'는 정직하고 취소도 된다. 그런데 **하루에 한 번 누르는 이 동작이 이 앱의 유일한 출구다.** 나는 하루를 고객별로 쪼개서 보고 싶은데, 만들 때 고를 수 있는 건 템플릿 셋뿐이고 "이 프로젝트만" 같은 선택지는 없다.
- **지난 날짜 이동과 "저장된 기록 · 18:42 갱신" · "기록만 남음" 배지는 정말 세심하다.** Claude 세션 로그가 30일 뒤 지워진다는 걸 알고 스냅샷을 떠두는 설계는 나한테 중요한 배려다. 단, **그건 앱을 깐 뒤부터 얘기다.** 설치한 첫 달, 나는 이전 3주치를 여전히 손으로 복원해야 했다.

### 일지 품질

샘플(표준 템플릿) 을 **청구서 첨부 후보**로 놓고 읽었다. 반은 쓸 만하고 반은 그대로는 못 낸다.

**쓸 만한 것.** '오늘의 성과'가 대괄호 프로젝트 태그로 시작한다. `template.rs` 의 지시문에 "주간보고에 그대로 옮겨 붙일 수 있는 문장으로 쓴다"고 되어 있는데, 실제로 그렇게 나온다. **청구서 '작업 내역' 칸에 거의 그대로 붙일 수 있는 수준이다.** '결정 · 요청 · 할 일'도 접두가 통일돼 있어서 월말에 grep 으로 긁어모으기 좋다.

**그대로는 못 내는 것.**

1. **숫자가 틀렸다.** 집중 표에 `agent-platform-backend 23h 32m`, 표 합계 26시간 이상인데 같은 문서의 지표 줄은 '활동 07:32–17:44'(약 10시간)다. `v2-plan` 에도 '같은 세션이 worktree 별로 3번 잡혀 집중시간이 과다 합산됨'이라고 이미 적혀 있는데, **아는 문제를 문서에는 그대로 내보내고 있고, 표 어디에도 "추정치"라는 말이 없다.** 나한테 이 표는 청구 근거인데, **이 숫자를 고객에게 보내면 사기다.** 2주 동안 이 표는 한 번도 못 썼다.
2. **타임라인이 원문 그대로다.** `<recommended_plugins>`, `The following is the Codex agent history…`, `보통 이런식으로 만들기도 하는거야 근데?` 같은 게 줄줄이 나온다. 같은 줄이 3번 반복되는 것도 있다. **내가 AI한테 반말로 던진 프롬프트가 고객 첨부 문서에 실린다는 뜻이다.**
3. **다른 고객 이름이 한 장에 섞인다.** 샘플 한 문서 안에 `agent-platform-backend`·`kms_backend`·`hotplace-poc`·`ai-web-novel` 이 다 있고, 타임라인엔 `Read D:\study\ai-web-novel\docs\…`, `C:/Users/owner/AppData/Local/Temp/claude/…` 같은 내 로컬 경로까지 박혀 있다. **A사에 보낼 문서에 B사 저장소 이름이 보이는 건 사고다.**
4. **지표 줄의 "출력 1.3M토큰".** 이건 내 작업량이 아니라 AI 사용량이다. **청구서에 붙으면 "그래서 사람이 한 게 뭐죠"라는 질문을 부른다.**
5. **'보고용' 템플릿이 내 용도와 엇갈린다.** 보고용은 집중 표가 빠진다. 내가 원하는 건 정확히 그 반대 — **프롬프트 원문 타임라인은 빼고 시간표는 남기는** 고객용이다. 그런 조합이 없고, 사용자 정의 템플릿은 보류라고 못박혀 있다.
6. **샘플 그날은 커밋 0이다.** 프롬프트 규칙 4번이 "git 커밋을 완료 결과의 1차 근거로 삼는다"인데 커밋이 없으니 **근거가 전부 내 프롬프트 텍스트다.** 설계 문서를 쓰거나 회의만 한 날(나는 그런 날이 주 2일쯤 된다)은 일지가 "AI한테 뭘 물어봤나"의 요약이 되어버린다.

### 설정

**설정은 이 앱에서 가장 나를 배려한 곳이다.**

'모양' 탭이 정확히 내가 좋아하는 종류다. 테마에 "시스템은 Windows 설정을 따릅니다" 힌트, 글꼴 3종에 실제 글꼴로 그려지는 미리보기 박스, 글자 크기 3단, 그리고 아래에 "빠른 메모 창에도 같이 적용됩니다" 한 줄. **이 마지막 문장이 쓸데없어 보여도 실제로는 "아, 두 창이 따로 놀지 않는구나"를 알려준다.** 나는 다크 + 둥근 고딕 + 크게로 맞춰놓고 2주 동안 손 안 댔다.

저장 버튼이 없고 머리글에 "변경 즉시 저장됨 · 17:31" 이 뜨는 것도 좋다. '정보' 탭에 설정 파일·데이터·일지 폴더 경로가 전부 나오고 각각 '폴더 열기' 버튼이 있다. **내 데이터가 어디 있는지 숨기지 않는 앱은 일단 신뢰가 간다.**

**아쉬운 건 두 가지 방향이다.**

- **개발자용 노브가 앞에 나와 있다.** "질답 상한 … 120턴 / 180자", "파일 행 상한 200000행", "탐색 깊이 5단계". 나는 이걸 올려야 일지가 좋아지는지 내려야 빨라지는지 판단할 근거가 없다.
- **없는 것 목록.** 프로젝트 → 고객 매핑이 없다. 저장소 **제외** 목록이 없다('직접 지정 저장소'는 추가만 된다). 프로젝트별로 AI 요약을 끄는 스위치가 없다. 월간 집계나 내보내기가 없다. 백업/복원도 없다. CLI 도 `--date` 로 하루씩만 되고 월 단위 옵션이 없어서 스크립트로 우회할 여지도 좁다.

**작성자 설정은 의외로 잘 돼 있었다.** "비우면 내 git 신원으로 자동 · 다른 이름·이메일로 남긴 커밋도 세려면 아래에 추가" — 나는 고객사마다 커밋 이메일이 다른데 '추가 작성자'로 세 개를 다 넣으니 잡혔다. **이건 고맙다.**

### 신뢰 · 프라이버시

이 항목은 점수를 반반 주겠다.

**믿음이 가는 쪽.** `v2-plan §0` 의 "로컬 전용… 세션 로그·코드가 외부로 나가지 않음", README 의 "요약을 쓸 때만 Claude 로 나간다", 그리고 설정 › 정보에 파일 경로를 다 까놓는 태도. 비밀값 처리도 좋다 — 화면에는 원값을 안 돌려주고 "비우면 현재 값 유지" 힌트만 있다. README 가 "비밀값이 들어 있으니 공유 금지" 라고 먼저 경고하는 것도, **숨기지 않아서 오히려 믿음이 간다**(평문인 건 별개로 마음에 안 들지만).

**불안한 쪽.** "요약을 쓸 때만 Claude 로 나간다"는 문장은 맞지만, **무엇이 나가는지는 앱 어디에도 없다.** 샘플 일지를 보고 나서 역산할 수밖에 없었다 — 타임라인에 내 프롬프트 원문과 `D:\study\…` 경로가 남아 있다는 건, 요약 요청에도 그게 다 실려 갔다는 뜻이다. 즉 **내가 A사 결제 코드를 붙여넣고 물어본 프롬프트가 요약 단계에서 한 번 더 나간다. A사 계약서엔 AI 도구 조항이 있다.** 나는 이걸 "아마 그럴 것이다"로 추정하고 싶지 않다. '지금 일지 만들기' 옆에 "이번에 나가는 내용 미리 보기" 버튼 하나면 끝날 문제다.

그리고 **전부 아니면 전무다.** 끄는 방법은 AI 요약을 통째로 "사용 안 함" 으로 바꾸는 것뿐인데, 그러면 B사·C사 일지까지 요약이 없어진다. **"A사 저장소는 AI에 안 보냄" 이 필요하다.**

**Notion 은 아예 안 켰다.** 켜는 순간 하루치 문서 전체가 Notion 서버로 올라가는데, 그 문서 안에 세 고객 이름이 섞여 있다. Obsidian(로컬 vault)만 쓴다.

마지막으로 자동 업데이트. minisign 서명 검증이 들어 있는 건 알겠는데, **사용자 화면에서는 "새 버전이 나왔습니다" 와 '지금 업데이트' 버튼뿐이고 그 검증에 대한 말이 한 줄도 없다.**

| 쓰임새 | 방법 |
|---|---|
| **결함 발견** | 리뷰가 짚은 지적 중 **코드·샘플로 재현되는 것만** 결함으로 승격한다. 위 "한눈에 보기"의 ✅ 항목 8개가 그렇게 승격되어 `docs/product-plan.md` §3 이 되었다 |
